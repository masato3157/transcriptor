# mp4文字起こしツール 設計書

- 日付: 2026-09-08
- ステータス: 承認待ち

## 概要

mp4動画ファイルを入力し、ローカル環境で音声認識(Whisper)による文字起こしを行うデスクトップツール。複数話者が存在する動画では話者分離を行い、GUI上で話者ラベルに実名を割り当てられるようにする。出力はTXT/SRT形式に対応し、TXT出力時はタイムスタンプの有無を設定で切り替えられる。

## 目的・成功基準

- mp4を選択するだけで、日本語音声を中心とした文字起こしがローカルで(API費用なしで)完了する。
- 複数話者の会話でも「誰が」「何を」話したかを判別・編集できる。
- 非エンジニアでも迷わず使える最小限のGUI。

## スコープ外

- 話者分離の話者数の事前指定・手動修正UI(区間の再割当てなど)は対象外。自動検出結果をそのまま採用する。
- クラウドAPI(OpenAI Whisper APIなど)への対応は対象外(将来拡張の可能性はあるが本設計には含めない)。
- リアルタイム(ストリーミング)文字起こしは対象外。

## アーキテクチャ

```
mp4ファイル
   │
   ▼
[audio_extractor] ffmpegで音声(wav, 16kHz mono)抽出
   │
   ▼
[transcriber] faster-whisperでセグメント単位の文字起こし(タイムスタンプ付き)
   │
   ▼
[diarizer] (任意・トグルでON/OFF) pyannote.audioで話者区間を検出
   │
   ▼
[merger] 文字起こしセグメントと話者区間を時間で突き合わせ、
         セグメントごとに話者ラベル(SPEAKER_00等)を付与
   │
   ▼
[GUI] 結果一覧表示 → 話者ラベルごとの実名入力欄 → エクスポート設定
   │
   ▼
[exporter] TXT / SRT ファイル出力(入力mp4と同じフォルダに保存)
```

### モジュール構成

`ClaudeCode_Whisper/` 配下:

- `audio_extractor.py` — ffmpegを呼び出し、mp4から16kHz monoのwavを一時ファイルとして抽出する。
  - 入力: mp4パス / 出力: wavパス(一時ファイル、処理終了後に削除)
  - 依存: システムのffmpeg実行ファイル(PATH上に必要)
- `transcriber.py` — faster-whisperを使い、wavからタイムスタンプ付きセグメントのリストを生成する。
  - 入力: wavパス、モデルサイズ、言語設定 / 出力: `[{start, end, text}, ...]`
  - 依存: `faster-whisper`
- `diarizer.py` — pyannote.audioを使い、話者区間のリストを生成する。
  - 入力: wavパス、HuggingFaceトークン / 出力: `[{start, end, speaker}, ...]`
  - 依存: `pyannote.audio`, `torch`
- `merger.py` — 文字起こしセグメントと話者区間を時間の重なりでマッチングし、セグメントに話者ラベルを付与する。話者分離を使わない場合は話者ラベルなしのまま素通しする。
  - 入力: 文字起こしセグメント、話者区間(Noneも可) / 出力: `[{start, end, speaker_label_or_None, text}, ...]`
  - 依存: なし(純粋なロジック、単体テスト容易)
- `exporter.py` — マージ済みセグメントと出力設定(形式、タイムスタンプ有無、話者名マッピング)から最終ファイル文字列を生成し保存する。
  - 入力: セグメントリスト、`{speaker_label: 実名}`のdict、出力形式、タイムスタンプ表示フラグ / 出力: 保存したファイルパス
  - 依存: なし
- `gui.py` — Tkinter画面。ファイル選択、設定、実行、結果表示、話者名入力、エクスポートの一連のUIを提供する。バックグラウンドスレッドで処理を実行しUIをブロックしない。
- `main.py` — エントリポイント。`gui.py`のアプリを起動する。
- `requirements.txt` — 依存パッケージ一覧。
- `README.md` — セットアップ手順(Python環境、pip install、ffmpeg確認、HuggingFaceトークン取得方法)、使い方。
- `.env.example` — `HF_TOKEN`等の設定例。

## GUI仕様

### メイン画面

- 「ファイルを選択」ボタン(mp4、複数選択可)。選択済みファイルを一覧表示。
- 設定欄:
  - モデルサイズ選択(例: `small` / `medium` / `large-v3`、デフォルト`large-v3`)
  - 言語(自動検出 / 日本語固定、デフォルト日本語固定)
  - 話者分離 ON/OFFトグル(デフォルトON)
  - 出力形式チェックボックス: TXT / SRT(両方選択可、デフォルト両方)
  - 「TXT出力にタイムスタンプを含める」チェックボックス(デフォルトON)
  - デバイス選択(自動 / CPU / GPU、デフォルト自動検出)
- 「実行」ボタン。押下でバックグラウンドスレッドにて処理開始。
- 進捗・ログ表示エリア(現在の処理ステップ、完了/エラー状況をテキストで表示)。

### 結果・話者名編集画面(処理完了後)

- 文字起こし結果一覧(タイムスタンプ・話者ラベル・テキスト)をスクロール可能なリストで表示。
- 話者分離ONの場合、検出された話者ラベル(`SPEAKER_00`など)ごとに名前入力用テキストボックスを動的生成。
- 「名前を反映してエクスポート」ボタン: 入力された実名でラベルを置換し、設定に従ってTXT/SRTファイルを生成・保存。
- 保存完了後、出力先フォルダを開くボタンを表示。
- 話者分離OFFの場合はこの画面の話者名入力欄は表示せず、そのままエクスポートボタンのみ表示。

複数ファイルを一括選択した場合は、ファイルごとに上記の結果・話者名編集フローを順に(または簡易的にタブ切り替えで)処理する。

## 出力フォーマット

### TXT(タイムスタンプON、話者分離ON)

```
[00:00:05] 田中: おはようございます。
[00:00:08] 鈴木: よろしくお願いします。
```

### TXT(タイムスタンプOFF、話者分離ON)

```
田中: おはようございます。
鈴木: よろしくお願いします。
```

### TXT(話者分離OFF)

タイムスタンプ設定に応じて、話者ラベルなしの全文(タイムスタンプ有無のみ切り替え)。

### SRT

標準SRT形式。話者分離ONの場合は各キューのテキスト先頭に`話者名: `を付与する。SRTはタイムスタンプがフォーマット上必須のため、TXTのタイムスタンプ設定の影響を受けない。

出力ファイルは入力mp4と同じフォルダに `<元ファイル名>.txt` / `<元ファイル名>.srt` として保存する。

## エラー処理

- ffmpeg未検出: 起動時またはファイル処理前にチェックし、GUI上にインストール案内メッセージを表示して処理を中断する。
- 非対応/破損ファイル: 該当ファイルの処理をスキップし、エラーログに詳細を表示。他ファイルの処理は継続する。
- モデルダウンロード失敗(ネットワークエラー等): エラーメッセージを表示し、再試行を促す。
- HuggingFaceトークン未設定・話者分離モデルの利用規約未同意: 話者分離が失敗した場合はエラーを表示しつつ、話者分離なしの結果にフォールバックするか確認する(ユーザーに選択させる)。
- 処理中の例外は全てキャッチし、GUIのログエリアに表示。アプリ全体がクラッシュしないようにする。

## 依存パッケージ(想定)

- `faster-whisper`
- `pyannote.audio`
- `torch`(CUDA対応版はGPU利用時、環境に応じてREADMEで案内)
- `python-dotenv`(HuggingFaceトークン管理用)
- 標準ライブラリ: `tkinter`, `threading`, `subprocess`, `pathlib`

実行環境の前提: Python 3.10、ffmpeg(PATH上に導入済み)、(任意)NVIDIA GPU + CUDA。

## テスト方針

- `merger.py`: 文字起こしセグメントと話者区間の時間重複マッチングロジックを単体テスト(境界条件: 区間またぎ、話者区間なし、等)。
- `exporter.py`: 各出力設定の組み合わせ(TXT×タイムスタンプ有無、SRT、話者分離あり/なし)でフォーマットが期待通りになることを単体テスト。
- `audio_extractor.py` / `transcriber.py` / `diarizer.py`: 外部ツール・モデル依存のため単体テストは最小限とし、実際のサンプル音声ファイルを使った手動確認(結合テスト)を中心に行う。
- GUI(`gui.py`): 手動での動作確認(ファイル選択→実行→話者名入力→エクスポートの一連のフロー)を実施。
